# Navio Web 预设编辑器设计

> 状态：设计冻结（2026-10-30）；A 静态原型已实现，尚未连接设备写入。
> 目标是直观、可恢复的预设编辑，不以功能数量牺牲清晰度。

## 1. 范围与原则

首版采用无框架原生 ES modules、SVG 俯视图和 GitHub Pages 静态部署。编辑器与刷写页互相链接，
但状态机与入口独立；复用 `navio_proto.js` 和 Config Protocol v2，不新增线上协议。

- 中央设备图直接点选，左侧预设库，右侧当前输入的动作面板。
- 修改先进入本地 dirty 状态，应用前校验并明确确认，不点选即自动写设备。
- 桌面 Chrome / Edge 优先；不支持实体键按下自动定位热点。
- 首版不做宏、多动作序列、长按映射、实时灯效预览或云端账号。

## 2. 页面与视觉布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 产品 / 当前预设 / 连接状态 / 导入导出 / 应用更改           │
├──────────────┬──────────────────────────┬───────────────────┤
│ 本地预设库   │ 可点击设备俯视图         │ 当前输入与动作    │
│ 新建/复制    │ 简短映射、选中与锁定状态   │ 映射 / 灯光页签   │
└──────────────┴──────────────────────────┴───────────────────┘
```

- 深蓝灰背景、橙色选中态、预设 accent 为辅助色；选中同时使用描边、放大和文本。
- 默认隐藏键名，已分配动作仅显示简短映射；悬浮展示键名与完整映射，未分配槽仅显示淡色加号。
- 编码器不在设备图上叠方向文字；选中后才在图外显示 CW/CCW/按压详情卡，完整编辑仍在右侧面板。
- 竖向滚轮使用矩形热点，其他旋钮使用圆形热点；选中描边贴合实际键帽而非外壳阴影。
- 键位显示简短映射；dirty、错误、锁定不能只靠颜色区分。
- 右侧“键位映射 / 灯光效果”是预留结构，首版只实现动作和 accent，不放假灯效按钮。
- 窄屏按预设库、设备图、动作面板的顺序单列，桌面 WebHID 仍为运行要求。

## 3. 渲染图与 SVG 资产

渲染图不是交互前提；先用矢量设备图。若使用原作者渲染图，要求：

- 正俯视、正交投影、方向与键位图一致，无透视拉伸；
- 整机与侧键完整可见，四周留白 5%–10%，透明背景、PNG/WebP、sRGB、长边至少 2048px；
- 柔和中性光，无遮挡、强反射、预设灯效、功能文字或水印；
- 可附 Blender/STEP/Fusion 源文件和斜视图用于展示，须允许修改与网页发布。

SVG 使用统一 `viewBox`：背景图（可选）→ 控件热点 → 映射文本 → 灯光预览 → 交互状态。
热点坐标与动作槽定义只维护一份数据。当前已具备符合上述规格的 `editor/assets/navio-chron-u1.png`，
静态原型采用该图作为背景并保留独立 SVG 热点与映射标签。

## 4. 槽位模型

全机 **21 个可编辑槽 + 1 个锁定槽**，共 22 个 5B Action：

- `actions[0..11]`：K1..K12；
- `actions[12..14]`：中央旋钮按压、大旋钮按压、滚轮下压；
- `actions[15]`：SideKey，锁定显示，读入→写回必须原样保留，不得清零；
- `actions[16..21]`：Center / Large / Wheel 的 CW、CCW，顺序与固件 `enc[ENC_COUNT][2]` 一致。

每个编码器使用一个热点，右侧面板并列 CW、CCW、按压三行，避免小热点难以点击。
`enc[0]=顺时针`，`enc[1]=逆时针`；旋转槽与按钮槽都允许 KeyChord / Consumer，旋转槽另允许 Wheel。

动作约束与 `docs/PRESET_SCHEMA.md` 一致：

- None：其余字段全 0；KeyChord：允许仅修饰键，空修饰+空键码非法；
- Consumer：code 1..0x03FF，mods=0；Wheel：仅非按钮槽，code=0，dy 为有符号非零格数；
- 键码选择采用常用子集 + 搜索 + 高级 Usage ID，KeyChord code≤0xE7，旋转格数 1..127。

## 5. 名称、身份与本地库

- 名称预算是 **1..23 个 UTF-8 字节**，不是 23 个字符；实时显示字节数，按码点边界拒绝，不截断。
- 本地库条目使用独立 UUID；设备记录使用 presetId 1..255，复制时不得隐式复用身份。
- localStorage 可保存本地库，根对象包含 `schemaVersion` 供迁移；设备身份不跨刷写会话持久化。
- `.navio.json` 包含格式版本、作者、平台标签与预设数据，只作交换，不直接写固件。
- 导入先进入本地库并完整校验，不静默覆盖本地或设备配置。

## 6. 设备 CRUD 语义

- `WRITE_PRESET` 是同 ID upsert：存在则原位替换，不存在则追加；满 6 套新 ID 被拒绝。
- 安装前用 GET_PRESETS 比对 ID，命中必须明确确认“替换『xxx』”。满容量安装让用户选择
  一套进行同 ID 覆盖，不先删后写；保留原顺序和 activeId。
- `MOVE [id][beforeId]` 使用锚点而非数组下标，beforeId=0 表示末尾；UI 操作须换算为锚点。
- 删除最后一套禁止并在 UI 预禁用；删除活动预设时设备自动切到第一套，确认文案必须说明，
  完成后重新读取 activeId。
- activeId 只能由设备侧键改变，页面在 window focus、重连和应用更改后刷新；首版不扩协议。
- GET_INFO 的 record 与 cmds 是能力门；不支持版本须迁移或明确拒绝。
- 满 6 套时 GET_PRESETS 走 MORE/READ_CHUNK，必须纳入验收。

## 7. 批量应用与恢复

WRITE_PRESET / MOVE 各自原子，但批量序列不是事务：

1. 应用前完成全部名称、动作、150B 编码、容量和 ID 冲突校验，失败则零写入。
2. 逐条提交，失败即停并显示“已应用 X/Y”，不伪装整体成功。
3. upsert 幂等允许安全重试；提供重新读取对账和导出备份。
- 150B 编解码使用 CRC-16/CCITT-FALSE，偏移 148；保留锁定槽、零填充和逐字节往返一致性。

## 8. 灯光与后续 UX 预留

Preset 数据分为 identity / metadata、actions、lighting，动作和灯光不混用字段。
设备图分为映射文字、灯光预览和交互状态三层。灯光页签未来承载 accent、模式与按键选项；
当前仅 accent + rgbMode=follow，LED_PREVIEW 未实现，不承诺实时设备灯效。

## 9. 阶段交付

- A：静态 SVG 原型、模拟预设、动作面板、本地库和导入导出，不接设备。
- B：连接读取、修改一个键位、应用并重读验证，形成最小闭环。
- C：完整新建/复制/删除/换序/安装覆盖、批量对账与本地库迁移。
- D：视觉与可访问性、官方预设库、灯光准备和完整验收。

`preset.js` 与 Node 测试先于设备联调，Pages 同时发布编辑器与刷写页。

## 10. 验收矩阵

- 21+1 槽位与方向、按压、锁定槽逐字节往返一致；CRC 位于 148。
- 同 ID 安装显式确认替换；满容量走同 ID 覆盖，不先删除。
- 中文/emoji 名称按字节拒绝，不产生半个字符；非法 UTF-8 不写入。
- 删除活动预设后设备切到第一套并刷新；最后一套不可删除。
- 批量失败显示 X/Y 且支持重读对账；非法输入和导入均零设备写入。
- 6 套满配的大响应读取通过；focus/重连后 activeId 正确。
- Chrome/Edge 中热点、键盘可达性、缩放、错误提示和本地库迁移可用。
