# Navio Web 预设编辑器设计

> 状态：A/B/C 设备能力已完成并真机验收；产品化 UX 阶段 1–4 均已完成。
> 阶段 4 已通过本地跨页与可访问性、窄屏/缩放、Pages 装配、线上及真机 WebHID 验收。
> 目标是直观、可恢复的预设编辑，不以功能数量牺牲清晰度。

## 1. 范围与原则

首版采用无框架原生 ES modules、SVG 俯视图和 GitHub Pages 静态部署。编辑器与刷写页互相链接，
但状态机与入口独立；复用 `navio_proto.js` 和 Config Protocol v2，不新增线上协议。

- 中央设备图直接点选，左侧区分预设库与键盘，右侧显示当前输入或整套灯光。
- 项目模板保持只读，右栏标题区提供“复制并编辑/编辑副本”并复用同一副本；我的预设与键盘预设直接开放控件，第一次有效修改即创建草稿，无需先点击编辑。
- 同一时间只有一套编辑会话；修改只存在于该会话，保存到我的预设或保存到键盘由用户显式执行。
- 本地修改不自动写设备，设备写入后必须重读并逐字节验证。
- 桌面 Chrome / Edge 优先；不支持实体键按下自动定位热点。
- 不做宏、多动作序列、长按映射、实时灯效预览或云端账号。

## 2. 页面与视觉布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 产品 / 工作区导航 / 连接状态 / 使用帮助                     │
├──────────────┬──────────────────────────┬───────────────────┤
│ 预设库/键盘  │ 当前预设与专用设备图     │ 当前输入与动作    │
│ 新建/导入    │ 名称、来源、平台、主题色   │ 映射 / 灯光页签   │
├──────────────┴──────────────────────────┴───────────────────┤
│ 当前保存位置与结果 / 编辑 / 放弃 / 保存或安装               │
└─────────────────────────────────────────────────────────────┘
```

- 使用浅灰新拟物材质、紫色交互强调与预设 accent；导航、预设列表与灯效卡片的当前项使用凹陷和紫色文本，设备图槽位保留选中描边。
- 灯效卡片及其缩略图默认保持平面，不显示单选圆点或选中描边；仅选中卡片整体凹陷，键盘焦点仍保留独立轮廓。
- 预设名称旁的主题色标识使用 28×12px 圆角横条，在几何居中基础上做 2px 光学校正；平台文字使用 12px 主文字色，与预设名称的文字基线对齐。
- SideKey 键面不显示名称，保留形状、焦点及“全局保留”的无障碍说明。
- 默认隐藏键名，已分配动作仅显示简短映射；悬浮、聚焦或选中时展示键名，未分配槽默认留空。
- 编码器不在设备图上叠方向文字；逆时针、顺时针与下压详情只在右栏呈现，中央不弹出详情层。
- 竖向滚轮使用矩形形状，其他旋钮使用圆形形状；圆形旋钮仅保留外部材质，不绘制内圈线条；控件形状本身就是热点，不再叠加透明定位框。
- dirty、错误、锁定不能只靠颜色区分；未保存状态由固定状态区表达，不在键帽上叠小点。
- “键位映射 / 灯光效果”位于当前预设标题行；灯光视图隐藏键位动作与状态灯灯芯，仅显示按键灯点和状态灯座。按键灯光按下/松开事件仅在灯光视图绑定，映射视图的只读与编辑状态都必须能选择全部键位。
- 首次加载项目模板时，预设名称、主题色和平台区域通过 `visibility:hidden` 保留布局但不显示静态占位；真实数据首次渲染后再显示，加载失败由固定状态区报告。主题色横条不做背景色过渡，避免首次显示时从默认紫色渐变到真实颜色。
- 窄屏按预设库、设备图、动作面板的顺序单列，桌面 WebHID 仍为运行要求。

## 3. 渲染图与 SVG 资产

正式编辑器使用 `editor/device_svg.js` 的专用 SVG：机身、键帽和编码器形状直接承载热点、映射文本、灯光与交互状态，
不依赖背景图。视觉几何独立维护，物理槽位仍以 `docs/hardware/HARDWARE_NOTES.md` 和固件矩阵为准
（K10=左、K11=下；2026-11-02 已核对）。不得仅凭渲染图或视觉位置推测 K 编号。

- K2、中央旋钮、K8 与 K11 共享中心线；中央旋钮与 K2/K8 等距，K9 位于其左下。
- 左侧滚轮与大旋钮共享中心线；K4/K7 与 K5/K6 分别同宽同 X，K6/K7 垂直居中。
- 三个状态灯以圆角横条呈现，从左到右为电源、连接、当前预设；tooltip 与可访问说明统一使用“上方电源/连接/预设指示灯”，不要求用户理解 LED 编号，不可编辑。
- 实物渲染图以后只可用于介绍或帮助，不参与编辑定位。

## 4. 槽位模型

全机 **21 个可编辑槽 + 1 个锁定槽**，共 22 个 5B Action：

- `actions[0..11]`：K1..K12；
- `actions[12..14]`：中央旋钮按压、大旋钮按压、滚轮下压；
- `actions[15]`：SideKey，锁定显示，读入→写回必须原样保留，不得清零；
- `actions[16..21]`：Center / Large / Wheel 的 CW、CCW，顺序与固件 `enc[ENC_COUNT][2]` 一致。

每个编码器使用一个热点，右侧面板按“逆时针、顺时针”旋转组 → 分割线 → 下压排列。
`enc[0]=顺时针`，`enc[1]=逆时针`；旋转槽与按钮槽都允许 KeyChord / Consumer，旋转槽另允许 Wheel。

动作约束与 `docs/PRESET_SCHEMA.md` 一致：

- None：其余字段全 0；KeyChord：允许仅修饰键，空修饰+空键码非法；
- Consumer：code 1..0x03FF，mods=0；Wheel：仅非按钮槽，code=0，dy 为有符号非零格数；
- 键码选择采用常用 HID Usage 子集，KeyChord code≤0xE7，旋转格数 1..127；
- 键盘选项按“字母 / 主键盘数字 / 主键盘符号 / 控制与编辑 / 导航 / 功能键 / 小键盘”分组，
  “仅修饰键”位于分组之外，分组元数据由 `preset.js` 统一维护。
- 修饰键按左右两组完整显示八项，右侧标为“右 Ctrl”等，不改变 HID 位映射。
- 小键盘选项在组内使用短标签，设备图与动作摘要保留“小键盘”前缀；数字与小数点提示 Num Lock 影响。
- 非法输入在字段附近显示，不以 toast 作为唯一错误提示。

## 5. 名称、身份与本地库

- 名称预算是 **1..23 个 UTF-8 字节**，不是 23 个字符。名称在标题行原地编辑，支持勾/叉、Enter/失焦确认和 Esc 取消；
  非法名称在行内提示，不截断、不产生半个字符。
- localStorage 写入失败时保留当前编辑会话，原预设对象不被提前修改；加载期回写失败不丢弃已读取的合法整库。
- 本地库条目使用独立 UUID；设备记录使用 presetId 1..255。复制时分配新 UUID 和本地 ID，不继承 `_installedId`。
- 本地库分为随页面发布的项目模板与浏览器保存的用户预设。模板不写入 localStorage，
  用户库使用 `{schemaVersion: 2, templateVersion, userPresets}`。
- 项目模板只读，只有显式“复制到我的预设”才创建独立副本；直接安装不要求先复制。
- 我的预设和键盘预设默认只读。保存到我的预设只更新浏览器；键盘预设就地编辑，不创建我的预设，保存时写回原设备 ID。
- 官方/键盘副本使用可选 `_originSourceKey`（`template:<slug>` 或 `device:<id>`）记录显式来源。
  重复复制打开已有副本；我的预设上的“复制”创建独立变体，不继承该来源关系。
- 来源关系不等于安装目标。项目/我的预设通过 `_installedId` 记录上次安装目标；项目模板的提示额外存入
  `navio-editor-template-installations-v1`，我的预设随本地库存储。目标被删除后关联失效，不得因 ID 巧合覆盖其他预设。
- 本地 `_dirty` 表示已保存内容与上次安装目标存在差异，不再表示跨预设未保存草稿；未保存内容只在当前编辑会话中。
- 旧 `originTemplateId` 只用于已有用户的模板升级决定；新的显式来源副本不继承模板更新绑定。
- 项目模板以 `editor/presets/` 下“一预设一 JSON”维护，索引由 `tools/build_templates.js` 生成并提交；
  单条损坏跳过并警示，索引或整库失败进入错误态，不静默降级。
- 项目模板共 28 套：JianYing、CapCut、Resolve、Premiere、After Effects、Blender、Illustrator、Photoshop、
  Lightroom Classic、Capture One、Clip Studio Paint、Krita 各有 Win/Mac，另有 Final Cut Pro Mac、Procreate iPad、F13 Macro、Test。
  顺序按剪辑/动效/3D、矢量/修图、绘画、工具排列；显示名不带平台词，平台由 chip 呈现；Mac/iPad 的 Cmd=左 GUI、Option=Alt。
- 主题色采用软件品牌或图标的识别色，同软件跨平台变体保持一致，Test 固定纯白；不使用随机配色。
  既有固件出厂预设的 accent 不随网页模板整理而改变。
- 应用键位优先参考公开 TourBox 等控制器模板，再按目标软件官方默认快捷键校对；只映射现有 HID 动作，
  不承诺 TourBox 专有插件、动态面板、宏或鼠标拖动能力。新模板仍需目标 App 实测微调。
- 项目模板列表按应用合并 Win/Mac 变体，并按视频剪辑、动效/3D、矢量/修图、数字绘画、工具分组；
  具体模板身份与安装关联仍使用原 slug。单平台模板保留 Mac/iPad 标识，不显示无效平台切换。
- 标题栏平台控件在双平台项目模板中切换版本，在我的预设/键盘中仍编辑当前预设平台；两种语义由来源决定，
  不修改记录内容以外的模板数据。切换项目模板版本不创建副本，也不隐式安装。
- 固定搜索框支持名称、别名、分类与平台关键词，只筛选项目模板；分组默认展开，搜索无结果显示明确空态。
  输入框有读屏标签和结果计数，列表选择继续使用 Enter/Space 与重绘焦点保留。
- 原生 `<select>` 保留键盘、读屏和弹出行为；关闭状态使用自定义箭头与右侧留白。
  Chromium 的 `select::-webkit-scrollbar` 使用与页面一致的细滚动条，其他浏览器回退原生滚动条；
  option/optgroup 统一文字、背景、间距与分组字重；Windows 原生弹出层的选中高亮仍由系统绘制，
  弹出层位置、动画和结构同样由浏览器负责，不为此自研下拉列表。
- `platform` 随 150B 记录 byte 13 落盘；设备图、动作面板和修饰键勾选框统一跟随，固件不按平台分支。
- 未知 schemaVersion 或整库损坏仍拒绝加载，原始存储保持不变；“备份并重建本地库”先下载原始数据，再经页面对话框确认。
- 单个非法条目按条隔离，其余预设照常可用；隔离条目不进入编辑或设备操作，原始字段在每次保存时原样写回。
- `.navio.json` 不携带 UUID、只读、来源、安装关系或 dirty 等页面内部状态。
- 导出对话框显示当前预设的只读格式化 JSON，支持复制和保存文件；两种输出由 `import_export.js`
  同源生成。导出打开时聚焦复制按钮，只读文本框用 `caret-color:transparent` 隐藏无编辑意义的插入光标；
  导入文本框保持正常光标。复制失败时选中文本并提示手动复制，不把剪贴板操作冒充文件下载。
- 导入对话框支持粘贴 JSON 与选择 `.json`/`.navio.json` 文件；文件先填入文本框，再由用户确认。
  两者共用 BOM、空内容、64KiB 上限、JSON 语法、产品/schema/record、平台和完整预设校验。
- 导入只进入我的预设并完整校验；本地 presetId 冲突时自动分配新 ID并明确提示，不覆盖原条目，
  不隐式写入键盘。校验失败或取消不改变当前状态；有未保存修改时沿用离开保护，继续编辑保留待导入文本。
- 删除我的预设必须经页面对话框确认，只删除浏览器副本，不影响键盘内容。

## 6. 单套编辑会话与离开保护

- 点击编辑后克隆当前对象作为 working；保存前不改变本地库或键盘中的原对象。
- 我的预设保存成功后更新浏览器库；键盘保存使用原 ID 写入、立即重读并逐字节验证。
- 切换预设、预设库/键盘视图或工作区时，如有未保存修改，提供“继续编辑 / 放弃修改 / 保存到当前位置”。
- 点击已经位于的视图是无操作；继续编辑为默认焦点，保存失败不关闭会话。
- 放弃修改后恢复原对象，不留下多份草稿；页面关闭或刷新前保留浏览器离开提示。
- 断线时保留正在编辑的键盘项目和工作内容，禁用保存到键盘；重连和后台读取不得覆盖 working。
- 首次连接默认选中键盘活动预设，但已选中“我的预设”时保留本地选择；窗口聚焦只在无编辑会话时刷新，手动重新读取不替换正在编辑的内容。

## 7. 设备 CRUD 与单项安装

- WebHID 执行 HELLO、GET_INFO、GET_PRESETS 和逐套 READ_PRESET；首次连接默认选中设备当前使用中的预设。
- 页头显示 `HELLO.fw`，并读取发布清单；仅设备版本严格低于发布版本时显示可更新提示，不阻断编辑。
- `WRITE_PRESET` 是同 ID upsert：存在则原位替换，不存在则追加；满 6 套新 ID 被拒绝。
- 项目/我的预设安装统一走页面对话框。存在上次安装目标时默认更新，不制造重复；
  只有显式勾选“作为新预设安装”且设备有空间时才新增。
- 满容量安装选择一套进行同 ID 覆盖，不先删后写；本地 UUID、presetId 和内容不因替换映射而改变。
- 所有写入成功后重新读取设备清单、顺序与 activeId；成功结果显示在固定操作区，不只使用短暂 toast。
- 键盘条目支持上移/下移和独立删除；卡片不放入口易混淆的复制图标，管理区分割线下方提供全宽复制按钮。
- 键盘顺序决定短按侧键的循环顺序；我的预设顺序只影响浏览器列表。
- 删除最后一套禁止并预禁用；删除使用中预设时确认文案说明设备会切到列表第一套。
- GET_INFO 的 record 与 cmds 是能力门；不支持版本须迁移或明确拒绝。满 6 套的大响应读取必须支持 MORE/READ_CHUNK。

## 8. 底层批量兼容

页面不再暴露“应用全部修改”或多套待写入草稿，只提供逐套写入。
`device.js` 的 `planBatch()` 与底层批量测试暂时保留用于兼容和回归，不构成用户界面功能。

WRITE_PRESET / MOVE 各自原子，但批量序列不是事务；若未来重新开放批量入口，仍必须完成全部预检、逐条确认、
失败即停、报告“已应用 X/Y”并自动重读对账，不得伪装整体成功。

150B 编解码使用 CRC-16/CCITT-FALSE，偏移 148；保留锁定槽、零填充和逐字节往返一致性。

## 9. 灯光

Preset 数据分为 identity / metadata、actions、lighting，动作和灯光不混用字段。
十种模式（含关闭）按 `off`、reactive、reactiveRandom、follow、breath、breathRandom、colorCycle、
rainbowFlow、marquee、rainbowMarquee 排列；`1=reactive` 为默认值，`0=off` 可主动选择，完整枚举见 D30 与 `PRESET_SCHEMA.md`。
具体时序与固件决策见 D26。LED0–LED2 状态灯不受模式影响。

网页提供纯本地灯效示意，不开发硬件 `LED_PREVIEW`，也不暗示实时控制设备；灯光列表保留“上方电源、连接和预设指示灯不受影响”，设备图下方固定提示“点击右侧卡片预览；网页示意不代表实机效果”。
`rgb_preview.js` 复现九种动态模式的时间曲线、物理外缘、随机种子与拖尾，off 保持全部按键灯熄灭；支持动态选择卡片、SVG 动画、
按键触发模拟、播放/暂停、重播、0.5×/1×/2×、重新随机和减少动态效果。页面不可见时停止动画。
缩略图统一为 4×4 外圈 12 点，中央 2×2 留空；`THUMB_RING_SLOTS` 只负责把物理外缘顺序映射到网格位置，
涂色按 `data-key` 读取引擎结果。响应脉冲、彩虹流动与两种跑马灯均与主预览共用 12 键数量、顺序和自然周期，不保留缩略图专用时间轴。

## 10. 阶段交付与验收

- A：静态 SVG 原型、模拟预设、动作面板、本地库和导入导出。
- B：连接读取、修改一个键位、应用并重读验证，形成最小设备闭环。
- C：设备新 ID 安装、删除/换序、满容量覆盖与底层批量对账，已真机验收。
- 产品化阶段 1：共享视觉、专用 SVG、统一导航与公开路由。
- 产品化阶段 2：步骤式固件更新、确认、救援、完成与高级选项。
