# Navio Web 预设编辑器设计

> 状态：设计冻结（2026-10-30）；A/B/C 均已完成并真机验收，包含双键盘拔插与换机重连验证；下一步 D 体验收尾。
> 目标是直观、可恢复的预设编辑，不以功能数量牺牲清晰度。

## 1. 范围与原则

首版采用无框架原生 ES modules、SVG 俯视图和 GitHub Pages 静态部署。编辑器与刷写页互相链接，
但状态机与入口独立；复用 `navio_proto.js` 和 Config Protocol v2，不新增线上协议。

- 中央设备图直接点选，左侧预设库，右侧当前输入的动作面板。
- 修改先进入本地 dirty 状态，应用前校验并明确确认，不点选即自动写设备。
- 桌面 Chrome / Edge 优先；不支持实体键按下自动定位热点。
- 首版不做宏、多动作序列、长按映射、实时灯效预览或云端账号。

## 2. 页面与视觉布局

```text
┌─────────────────────────────────────────────────────────────┐
│ 产品 / 当前预设 / 连接状态 / 导入导出 / 应用更改           │
├──────────────┬──────────────────────────┬───────────────────┤
│ 本地预设库   │ 可点击设备俯视图         │ 当前输入与动作    │
│ 新建/复制    │ 简短映射、选中与锁定状态   │ 映射 / 灯光页签   │
└──────────────┴──────────────────────────┴───────────────────┘
```

- 深蓝灰背景、橙色选中态、预设 accent 为辅助色；选中同时使用描边、放大和文本。
- 默认隐藏键名，已分配动作仅显示简短映射；悬浮展示键名与完整映射，未分配槽仅显示淡色加号。
- 编码器不在设备图上叠方向文字；选中后才在图外显示 CW/CCW/按压详情卡，完整编辑仍在右侧面板。
- 竖向滚轮使用矩形热点，其他旋钮使用圆形热点；选中描边贴合实际键帽而非外壳阴影。
- 键位显示简短映射；dirty、错误、锁定不能只靠颜色区分。
- 右侧“键位映射 / 灯光效果”是预留结构，首版只实现动作和 accent，不放假灯效按钮。
- 窄屏按预设库、设备图、动作面板的顺序单列，桌面 WebHID 仍为运行要求。

## 3. 渲染图与 SVG 资产

渲染图不是交互前提；先用矢量设备图。若使用原作者渲染图，要求：

- 正俯视、正交投影、方向与键位图一致，无透视拉伸；
- 整机与侧键完整可见，四周留白 5%–10%，透明背景、PNG/WebP、sRGB、长边至少 2048px；
- 柔和中性光，无遮挡、强反射、预设灯效、功能文字或水印；
- 可附 Blender/STEP/Fusion 源文件和斜视图用于展示，须允许修改与网页发布。

SVG 使用统一 `viewBox`：背景图（可选）→ 控件热点 → 映射文本 → 灯光预览 → 交互状态。
热点坐标与动作槽定义只维护一份数据。当前已具备符合上述规格的 `editor/assets/navio-chron-u1.png`，
静态原型采用该图作为背景并保留独立 SVG 热点与映射标签。
热点排布已与 `docs/hardware/HARDWARE_NOTES.md` 物理位表逐键核对（2026-11-02 修正 K10/K11 热点对调：
左=K10、下=K11，与固件矩阵及上游 layer0 一致；渲染图无法判定 K 编号，勿再按图猜位）。

## 4. 槽位模型

全机 **21 个可编辑槽 + 1 个锁定槽**，共 22 个 5B Action：

- `actions[0..11]`：K1..K12；
- `actions[12..14]`：中央旋钮按压、大旋钮按压、滚轮下压；
- `actions[15]`：SideKey，锁定显示，读入→写回必须原样保留，不得清零；
- `actions[16..21]`：Center / Large / Wheel 的 CW、CCW，顺序与固件 `enc[ENC_COUNT][2]` 一致。

每个编码器使用一个热点，右侧面板并列 CW、CCW、按压三行，避免小热点难以点击。
`enc[0]=顺时针`，`enc[1]=逆时针`；旋转槽与按钮槽都允许 KeyChord / Consumer，旋转槽另允许 Wheel。

动作约束与 `docs/PRESET_SCHEMA.md` 一致：

- None：其余字段全 0；KeyChord：允许仅修饰键，空修饰+空键码非法；
- Consumer：code 1..0x03FF，mods=0；Wheel：仅非按钮槽，code=0，dy 为有符号非零格数；
- 键码选择采用常用子集 + 搜索 + 高级 Usage ID，KeyChord code≤0xE7，旋转格数 1..127。

## 5. 名称、身份与本地库

- 名称预算是 **1..23 个 UTF-8 字节**，不是 23 个字符；实时显示字节数，按码点边界拒绝，不截断。
  IME 组合中和暂时空名只更新计数、不写模型，最终提交非法名称或失焦仍非法时才回退；副本名称先校验再创建。
  localStorage 写入失败只保留当前页面状态并明确提示；加载期回写失败不得丢弃已经成功读取和校验的整库。
- 本地库条目使用独立 UUID；设备记录使用 presetId 1..255，复制时不得隐式复用身份、继承 `_installedId` 或模板更新绑定。
- 本地库分为随页面发布的官方模板与浏览器保存的用户预设。模板只读，编辑模板时先自动创建用户副本；
  模板不写入 localStorage，用户库使用 `{schemaVersion: 2, templateVersion, userPresets}`。
- 官方模板以 `editor/presets/` 下"一预设一 JSON"维护，不再硬编码在 app.js。信封沿用 `.navio.json`
  导出格式并要求 `metadata.templateId`（=文件名 slug）、`metadata.order`（展示顺序）与可选
  `description`/`author`；`templateId` 仍是用户副本关联的身份（见上）。浏览器不能列目录，索引
  `presets/index.json` 由 `tools/build_templates.js` 构建期生成并提交入库；CI 与
  `editor/templates_test.js` 校验信封、150B 往返、slug/ID 唯一、索引漂移与固件逐槽基线。
  贡献流程：编辑器导出 `.navio.json` → 放入 `presets/` 补 metadata → 跑生成脚本 → 提 PR。
- 编辑器启动异步拉取模板：单条损坏跳过并警示；索引或整库失败进入错误态提示刷新，不静默降级；
  官方文件的 `preset.platform` 严格校验（用户导入文件才做静默归一）。
- 官方模板共 9 套：`JianYing`（Win/Mac）、`Resolve`（Win/Mac）、`Premiere`（Win/Mac）、
  `Procreate`（iPad）、`Test`、`F13 Macro`。显示名不带平台词，平台由预设库列表的 chip 呈现。
  Mac 变体 Cmd=左 GUI（mods 位 3）、Option=Alt；快捷键按官方文档填写，以目标 App 实测为准微调。
- 官方模板的身份是代码内固定的 `templateId` slug（如 `jianying-win`），与显示名解耦：模板改名、
  改文案不断链。用户副本以 `originTemplateId` 记 slug，`syncTemplates` 按 slug 匹配；
  模板 `uuid` 是运行时会话标识，不作持久身份。项目无存量用户，身份字段变更不做迁移。
- 修饰键文案按预设的 `platform` 显示（`win`/`mac`/`ipad`，默认 `win`，本地库非法值加载时矫正为 `win`）：
  mac 与 iPad 共用 `Ctrl/Shift/Opt/Cmd` 短词，win 沿用 `Ctrl/Shift/Alt/Win`；设备图、动作面板、
  详情卡、修饰键勾选框与列表 chip 统一跟随。`platform` 随 150B 记录落盘（byte 13，D24）：
  设备读回即有真实平台，chip 覆盖设备分区；平台改动与主题色同等对待——标 dirty、随应用写入设备。
- 旧 `schemaVersion: 1` 库迁移时去除未修改的出厂示例，保留用户修改并记录来源模板。
  官方模板升级时逐套明确询问是否替换，保留本地 UUID、设备 presetId 和用户名称，不静默覆盖；
  接受或拒绝的决定立即写入 localStorage，后续启动不重复询问。合法旧库加载时会清除页面内部标志并保存清理结果。
- localStorage 可保存用户预设；设备身份不跨刷写会话持久化。
- 未知 schemaVersion 或整库损坏仍拒绝加载，原始存储保持不变，本次页面禁止保存；
  “备份并重建本地库”先下载原始数据，再经明确确认写入空库，不要求用户使用开发者工具恢复。
- 单个非法条目按条隔离，其余预设照常可用；隔离条目不进入编辑或设备操作，原始字段在每次保存时原样写回，
  状态栏持续显示跳过数量。只有用户显式清空或重建本地库时才删除隔离条目。
- `.navio.json` 只包含格式版本、作者、平台标签与设备预设数据，不携带 UUID、只读、设备来源或 dirty 等页面内部状态。
- 导入先进入本地库并完整校验，不静默覆盖本地或设备配置；本地 presetId 冲突时自动分配新 ID 并明确提示。
- “删除当前自定义预设”只删除浏览器本地副本，确认文案明确设备内容不变；官方模板和设备分区不可由此删除。

## 6. 设备 CRUD 语义

- B 阶段通过 WebHID 执行 HELLO、GET_INFO、GET_PRESETS 和逐套 READ_PRESET；设备预设单独分区、只读，
  首次编辑时创建同 presetId 的本地副本。窗口聚焦和手动“重新读取”会刷新设备清单与 activeId。
- 每次新连接取得 `HELLO.fw` 后在页头以独立标签显示当前设备固件版本，并主动读取发布清单
  （线上为站点根目录 `manifest.json`，本地为当前 `release/navio_chron_0.5.12/manifest.json`），
  复用刷写规则的完整 SemVer 比较；仅设备版本严格低于发布版本时显示顶部更新条
  与刷写入口，同版或更新版本不提示。检查异步执行，清单加载或版本解析失败只记录诊断，不阻断
  设备读取与预设编辑；断开后隐藏版本标签并清除更新提示。
- B 阶段仅开放已有同 ID 的覆盖：写入前校验并明确确认，WRITE_PRESET 后立即 READ_PRESET，
  150B 逐字节一致才显示成功并清除本地 dirty；新 ID 安装、删除和换序留到 C 阶段。
- `WRITE_PRESET` 是同 ID upsert：存在则原位替换，不存在则追加；满 6 套新 ID 被拒绝。
- 安装前用 GET_PRESETS 比对 ID，命中必须明确确认“替换『xxx』”。满容量安装让用户选择
  一套进行同 ID 覆盖，不先删后写；保留原顺序和 activeId。
- C 阶段允许官方模板或本地预设直接安装；满容量时在对话框选择目标，使用目标 ID 生成设备写入副本，
  本地 UUID、presetId 和内容不因替换映射而改变。成功写入后在本地记录 `_installedId` 槽位提示，
  后续单项和批量安装优先复用仍存在的槽位；槽位缺失不强制沿用，非法提示在加载时剥离，批量映射冲突必须在零写入前拒绝。
- 设备条目支持上移/下移和独立“从设备删除”；本地删除按钮只影响“我的预设”。
- `MOVE [id][beforeId]` 使用锚点而非数组下标，beforeId=0 表示末尾；UI 操作须换算为锚点。
- 删除最后一套禁止并在 UI 预禁用；删除活动预设时设备自动切到第一套，确认文案必须说明，
  完成后重新读取 activeId。
- activeId 只能由设备侧键改变，页面在 window focus、重连和应用更改后刷新；首版不扩协议。
- GET_INFO 的 record 与 cmds 是能力门；不支持版本须迁移或明确拒绝。
- 满 6 套时 GET_PRESETS 走 MORE/READ_CHUNK，必须纳入验收。

## 7. 批量应用与恢复

WRITE_PRESET / MOVE 各自原子，但批量序列不是事务：

1. “应用全部修改”只收集 dirty 用户预设；完成全部名称、动作、150B 编码、重复 ID 和容量预检，
   失败则零写入。批量新 ID 超容量时明确拒绝，目标替换通过单项安装完成；确认文案必须逐条列出
   `_installedId` 重定向涉及的本地预设、被覆盖设备预设和目标 ID。
2. 预检后对快照逐条提交，失败即停并显示“已应用 X/Y”，随后重新读取设备，不伪装整体成功；
   若重读也失败，必须明确提示用户手动重新读取，不得宣称设备状态已刷新。
3. upsert 幂等允许安全重试；提供重新读取对账和导出备份。
- 150B 编解码使用 CRC-16/CCITT-FALSE，偏移 148；保留锁定槽、零填充和逐字节往返一致性。

## 8. 灯光与后续 UX 预留

Preset 数据分为 identity / metadata、actions、lighting，动作和灯光不混用字段。
设备图分为映射文字、灯光预览和交互状态三层。灯光页签提供 `reactive`（默认，按下保持、
松开 500ms 渐隐）/ `breath`（8 秒 smoothstep 变化 + 最亮/最暗端各 500ms 保持，共 9 秒）/ `follow`（常亮）三选一，均使用预设 accent，
随预设保存并在安装或应用修改后生效。LED0–LED2 状态灯不受模式影响，不按 USB/BLE 切换。
LED_PREVIEW 未实现，不承诺实时设备灯效。

## 9. 阶段交付

- A：静态 SVG 原型、模拟预设、动作面板、本地库和导入导出，不接设备。
- B：连接读取、修改一个键位、应用并重读验证，形成最小闭环。
- C：设备新 ID 安装、设备删除/换序、满容量覆盖与批量对账。
- D：视觉与可访问性、模板内容扩充、灯光准备和完整验收
  （首批平台模板已提前上线：Premiere Win/Mac、Resolve/剪映 Mac、Procreate iPad）。

`preset.js` 与 Node 测试先于设备联调，Pages 同时发布编辑器与刷写页。

## 10. 验收矩阵

- 21+1 槽位与方向、按压、锁定槽逐字节往返一致；CRC 位于 148。
- 同 ID 安装显式确认替换；满容量走同 ID 覆盖，不先删除。
- 中文/emoji 名称按字节拒绝，不产生半个字符；非法 UTF-8 不写入。
- 删除活动预设后设备切到第一套并刷新；最后一套不可删除。
- 批量失败显示 X/Y 且支持重读对账；非法输入和导入均零设备写入。
- 6 套满配的大响应读取通过；focus/重连后 activeId 正确。
- rgbMode 0/1/2 逐字节往返；默认 reactive 按住常亮、松开渐隐，breath/follow 与状态灯互不干扰。
- Chrome/Edge 中热点、键盘可达性、缩放、错误提示和本地库迁移可用。
