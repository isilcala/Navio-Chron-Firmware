# Navio Web 产品化 UX/UI 重构

> 状态：原型已评审；阶段 1 共享视觉、专用 SVG 与公开路由、阶段 2 固件任务流程、
> 阶段 3 正式编辑器交互均已实现。阶段 4 的跨页、可访问性、窄屏/200% 缩放、
> Pages 装配、线上与真机 WebHID 验收均已完成。
> 范围：统一外壳、预设编辑器、固件更新、视觉与文案。现有设备协议、150B 记录、
> OTA/ROM 决策、本地库格式和写入安全规则不在本轮 redesign 的改写范围内。

## 0. 阶段 0.5 可交互原型

> **注（2026-11-12）**：`prototype/` 目录已在正式编辑器上线后移除，本节保留为设计过程记录。

原型位于 `prototype/`。在仓库根目录运行 `python -m http.server 8000` 后打开
`http://localhost:8000/prototype/`。页面使用模拟数据和专用 SVG 键盘，左下角控制面板可切换
两个工作区及关键场景；收起控制面板即可查看完整视觉布局。

原型支持预设选择、设备热点、键位/灯光切换、创建与复用本地副本、轻量名称/平台/颜色设置、
单项写入确认、工作区导航和模拟固件更新。它不调用 WebHID/Web Serial，不读写 localStorage，不执行真实设备写入，也不接入
公开部署。阶段 0.5 评审通过后，才以其为基准进入正式外壳与路由改造。

## 1. 产品目标

把两个开发期工具整理为同一个面向终端用户的产品：

- 根页面服务最高频的预设编辑，固件更新作为独立的低频工作区。
- 用户无需理解 WebHID、Web Serial、ROM、NVS、分区或协议即可完成常见任务。
- 每个页面都有明确的当前对象、当前状态和唯一下一步主操作。
- 本地编辑与设备写入始终可区分；危险操作必须说明影响范围。
- 首次使用、日常编辑、版本更新和异常恢复都有可理解的出口。

非目标：

- 不为了“整合”而把两个任务塞进同一屏或改成完全单页应用。
- 不新增云端账号、在线同步、宏编辑或实时硬件灯效承诺。
- 不改变“本地修改不自动写设备”和“覆盖前显式确认”的既有语义。

## 2. 路由与统一外壳

### 2.1 公开路由

| 路由 | 工作区 | 说明 |
|---|---|---|
| `/` | 预设编辑器 | 默认首页，允许未连接时浏览和编辑 |
| `/firmware/` | 固件更新 | 首次安装、版本更新和 BOOT 救援 |
| `/editor/` | 兼容入口 | 跳转到 `/`，保留已有书签和外部链接 |

本地开发探针可以保留原路径用于回归，但公开部署只把上述路由作为用户入口。
根地址切换后必须同步 Pages 装配、页面内链接、更新提示和 README，不留下指向旧首页的隐性依赖。

### 2.2 统一顶栏

```text
┌──────────────────────────────────────────────────────────────────┐
│ Navio Chron       预设   固件更新              设备状态   使用帮助 │
└──────────────────────────────────────────────────────────────────┘
```

- 当前工作区使用文字、下划线和 `aria-current` 同时标识，不只依赖颜色。
- “预设”工作区在右侧提供连接按钮；连接后显示固件版本和设备状态。
- “固件更新”工作区的连接动作位于任务卡片中，顶栏不增加另一个含义不同的连接按钮。
- 使用帮助只提供连接要求、预设切换和救援入口等用户内容，不链接开发文档。
- 固件写入期间禁用工作区导航，并在页面离开前提示风险。

两个页面共享设备状态的视觉语言，但第一阶段不承诺跨路由保持同一个 WebHID 会话。
浏览器已经授权的设备可由目标页面重新取得；需要用户手势时，由目标页面明确提示连接。

## 3. 核心用户流程

### 3.1 日常编辑

```text
打开根页面
→ 选择项目模板、我的预设或键盘预设
→ 点击编辑并修改键位与灯光
→ 保存到我的预设或保存到键盘
→ 我的预设需要时另行明确安装或更新
→ 设备写入后重读验证
→ 显示设备结果
```

### 3.2 首次使用或固件更新

```text
打开固件更新
→ 检查浏览器和发布包
→ 选择“连接并检查更新”或“串口模式刷写”
→ 展示当前/目标版本与预设保留结果
→ 用户确认
→ 写入并显示阶段进度
→ 显示“写入完成，设备正在重启”
→ 提供“去配置预设”入口和“返回上一步”次按钮
```

### 3.3 救援

```text
自动路径无法继续
→ 停止自动尝试
→ 显示正常、非惩罚性的救援页面
→ 按图完成 BOOT 操作
→ 用户点击明确的继续按钮
→ 回到确认与写入流程
```

### 4.2 左栏：区分本地库与键盘管理

左栏只提供“预设库”和“键盘”两个一级视图：

- **预设库**：我的预设置于项目模板之前；两组在同一滚动列表中呈现，不再增加 Tab。
- **我的预设**：显示未安装、已安装但有修改或与键盘一致，并用名称指出上次安装目标。
- **项目模板**：保持只读，可显式复制到我的预设或直接安装；修改项目模板不会自动复制。
- **键盘**：显示 `已安装 n/6`、当前使用中的预设，以及顺序调整和删除；当前编辑会话只存在于原项目上，不进入我的预设。
- 未连接时键盘视图显示空状态；正在编辑的项目仍保留并标记断开，禁止保存到键盘。
- 首次连接成功后默认选中键盘当前使用中的预设，但当前已选中“我的预设”时保留该选择；后续后台刷新不打断用户正在编辑的本地预设。
- 新建、导入、“导出当前”放在预设库顶部的常驻工具栏，明确导出只作用于当前预设。
- 取消三点菜单；项目/我的预设卡片内提供带 tooltip 的复制图标，我的预设删除必须弹窗确认。
- 键盘卡片不放复制图标；在顺序与删除管理区下方用分割线隔开全宽“复制到我的预设”，已有副本时改为“打开我的副本”。
- 键盘管理区说明“预设顺序决定短按侧键时的循环顺序”；删除使用中预设必须确认并提示回退到列表第一套。

### 4.3 中栏：预设身份与编辑模式

- 当前预设名称、来源、平台和主题色集中在设备图上方，不再提供独立“预设设置”弹窗。
  首次模板加载期间隐藏这组动态内容但保留布局空间，真实数据就绪后再显示；主题色横条不做背景色过渡，避免静态名称或默认紫色短暂闪现。
- 点击名称 inline 改名；提供勾/叉按钮，同时保留 Enter/失焦确认和 Esc 取消，继续遵守 23B 名称限制。
- 点击平台标签打开轻量选择框；点击名称旁清晰可见的主题色块打开颜色选择面板。
  主题色标识使用 28×12px 圆角横条并做 2px 向下光学校正；平台文字使用 12px 主文字色，与预设名称的文字基线对齐。
- 主题色用于预设标识和支持主题色的灯光效果；彩虹等忽略主题色的模式不影响其标识用途。
- “键位映射 / 灯光效果”以分段按钮放在标题行右侧，是工作区模式切换，不是选中键的子属性。
- 使用 `prototype/device.js` 的专用 SVG 键盘：键帽/旋钮形状即交互区域，不再叠加实物位图与透明热点；保留 Navio 物理拓扑、映射摘要、选中态和编码器三槽详情。
  圆形旋钮不绘制浅灰内圈，以外部材质和阴影表达形状，避免同心圆层级干扰动作文字。
- 灯光视图提供纯网页示意预览；灯光列表保留“上方电源、连接和预设指示灯不受影响”，设备图下方固定提示“点击右侧卡片预览；网页示意不代表实机效果”，不暗示实时硬件预览；状态灯 tooltip 使用相同职责名称。
  桌面端右栏的标题与当前灯效说明保持 sticky 可见，只有后续分组卡片滚动；窄屏自然布局不启用。
  选择卡片按“基础 / 按键触发 / 整体变化 / 流动拖尾”分组并显示灯效缩略图，默认选择按键响应，可主动关闭；中央 SVG 与缩略图共用纯 JS 引擎，
  支持播放控制、按键触发和减少动态效果。缩略图采用 4×4 外圈 12 点、中央 2×2 留空，灯效数量、顺序和周期与主预览一致；网格槽位仅负责视觉定位。明确不开发硬件 `LED_PREVIEW`。
- SideKey 保持可见、可查看和不可编辑，键面不显示名称，通过焦点与无障碍说明表达其全局用途。

### 4.4 右栏：统一编辑当前对象

- 键位映射视图显示当前键位；编码器按“逆时针、顺时针”旋转组 → 分割线 → 下压排列。
- 编码器详情只在右栏呈现，不再弹出中央底部详情层；桌面工作区高度固定，长检查器自行滚动，避免键盘区域跳动。
- 灯光视图显示整套预设的灯光选项，不显示无关的键位标题。
- 空状态给出“点击设备上的键位或旋钮开始编辑”。
- 动作类型变化后只显示相关字段；非法输入在字段附近说明，不使用页面底部 toast 作为唯一错误提示。
- 修饰键按左侧/右侧分组完整显示八个选项；右侧使用“右 Ctrl”等标签，保留原 HID 位映射。
- 项目模板保持只读，右栏标题区显示“复制并编辑”并直接进入副本编辑；已有副本时显示“编辑副本”，始终复用同一副本。
- 我的预设与键盘预设不提供开始编辑按钮，控件直接可操作；第一次有效配置修改创建草稿。仅查看、切换键位或灯光预览不进入编辑。
- 不再使用随键位重复的凹陷只读说明卡或空说明框；SideKey 等锁定对象不提供编辑按钮。

### 4.5 固定状态与单项主操作区

底部操作区位置保持稳定，始终回答是否正在编辑、修改将保存到哪里。非编辑时承担安装/更新，首次修改后切换为保存与放弃，不因出现或隐藏造成布局跳动。

| 当前对象 | 状态文案 | 主操作 |
|---|---|---|
| 项目模板，只读 | 可直接安装，或在右栏复制并编辑 | 安装到键盘 |
| 我的预设，只读 | 浏览器中的独立预设，可直接修改 | 安装/更新 |
| 我的预设，编辑中 | 修改尚未保存到我的预设 | 保存到我的预设 |
| 键盘预设，只读 | 可直接修改，保存前键盘不会改变 | 无 |
| 键盘预设，编辑中 | 修改尚未保存到键盘 | 保存到键盘 |
| 键盘已连接且有已保存修改 | 上次安装目标尚未更新 | 更新键盘中的此预设 |
| 保存失败或键盘断开 | 保留当前编辑会话并说明原因 | 禁止伪装成功 |

- 同一时间只能编辑一套预设；编辑其他对象前必须保存或放弃当前修改。
- 点击已经位于的工作区或库/键盘 Tab 是无操作，不触发未保存提示。
- 编辑中提供直白的“放弃修改”，不使用含义模糊的“取消编辑”。
- 我的预设保存只写入浏览器，不自动写键盘；键盘保存写入并读回验证。
- 隐式进入编辑时保留正在操作的控件值与焦点；保存或主动放弃后聚焦当前预设名称。
- 不提供“应用全部待更新”入口，也不保留多套未保存草稿。
- 写入期间显示进行状态；成功后在操作区保留结果，不用 3 秒 toast 作为唯一成功证据。

### 4.6 关键编辑器状态

1. **首次进入**：默认展示首个项目模板，提供“选择模板开始，也可连接键盘读取现有配置”的轻量提示。
2. **复制项目模板**：只有显式复制或“复制并编辑”才创建独立副本；后者直接进入编辑。已有副本执行“编辑副本”，不覆盖、不默认重复。
3. **统一编辑会话**：我的预设与键盘预设在第一次有效修改时自动创建草稿，同一时间仅一套可编辑；项目模板仍显式复制。
4. **离开未保存修改**：真正切换预设、库/键盘或工作区时，提供“继续编辑 / 放弃修改 / 保存到当前位置”。
5. **安全默认**：继续编辑是默认焦点；保存失败不断开当前会话；键盘断开时保留当前项目和工作内容，禁用保存到键盘；重连不主动覆盖编辑内容。
6. **复制键盘预设**：非编辑状态下显式复制为独立我的预设；重复操作打开已有副本，更多变体从我的预设显式复制。
7. **安装项目/我的预设**：首次有空间则新增，满员则选择替换；成功后记住上次安装目标，再次安装默认更新该项而非制造重复。
8. **显式新增**：已有安装目标且键盘有空间时，可勾选“作为新预设安装”，只有此时才新增并保留原目标。
9. **本地库异常**：持续显示恢复入口；备份并重建前仍需明确确认。
10. **固件有更新**：提示“可更新”，不写成必须停止编辑的强制要求。

### 4.7 三类预设与两种关系

项目模板是只读来源，我的预设是用户拥有的独立浏览器文档，键盘预设是设备实际使用的内容。
三者没有自动双向同步；名称相同不代表身份相同。编辑会话是当前页面的临时状态，不是另一套持久预设。

- **来源关系**：官方/键盘显式复制到我的预设时记录来源，仅用于打开已有副本和展示出处，不代表写回目标。
- **安装关系**：项目/我的预设记住上次安装到键盘哪一项，仅用于再次安装时默认更新目标。
- 键盘编辑会话只关联当前原项目，保存或放弃后即结束，不产生持久草稿或我的预设。
- 显式复制产生的我的预设独立于来源；首次安装不默认覆盖来源项目。
- 上次安装目标被删除后，关联自然失效，下次按新预设安装。
- 删除我的预设必须确认，且不删除键盘内容；删除键盘预设不删除我的预设。
- 我的预设顺序只影响浏览器列表；键盘预设顺序决定侧键循环顺序。
- 普通界面不展示 presetId 或内部槽位，只用名称、来源和上次安装目标表达关系。

### 5.2 检查与确认

```text
当前版本  0.5.20
目标版本  0.5.23

更新方式  应用内更新
数据影响  将保留你的预设

注意事项  更新期间请保持 USB 连接，不要关闭页面。

[取消]  [开始更新]
```

- 已是最新版时显示“你的设备已是最新”，提供“去配置预设”主按钮和“返回上一步”次按钮。
- 首次安装、升级、重装和降级使用各自准确的标题与按钮。
- 已知 Navio 明确显示“将保留你的预设”；未知串口设备单独突出擦除范围。
- 所有自动写入前都经过此确认状态，不因重复点击或重试绕过。

### 5.3 写入中

```text
正在更新固件
[==================----------------] 62%

正在写入设备，请保持 USB 连接。
不要关闭页面或拔出设备。
```

- 进度条同时有文本百分比和阶段说明。
- 写入中隐藏或禁用无关按钮，不提供会造成误解的取消写入操作。
- 技术日志继续记录，但默认不占据页面。

### 5.4 完成

```text
刷写完成
设备会自动重启。前往配置预设后，请在新页面再次点击“连接设备”。

[返回上一步]  [去配置预设]
```

“完成”只表示镜像写入、校验和重启指令已完成，不宣称网页已验证重启后的版本、槽位或预设。
若镜像已完整写入但自动重启异常，则显示“固件已写入，自动重启未完成”及手动重启方法，不把复位异常
误报为写入失败。

### 5.5 救援与错误

救援采用独立指导状态，不使用红色错误页：

```text
需要一次手动连接

1. 拔下 USB。
2. 按住设备上的 BOOT 键。
3. 保持按住并插入 USB，然后松开。
4. 点击下方按钮继续。

[我已完成，选择设备]
```

- 配图必须与实际硬件和当前救援路径一致，不新增未经确认的侧键手势。
- 每一步只保留一个主按钮；救援连接使用指导卡内的独立按钮，不改变首屏两个入口的功能。
- 可重试错误显示“重试”；需要恢复时显示“使用救援方式”；manifest 或镜像校验失败不得提供绕过确认的入口。
- 错误状态明确是否已经开始写入，以及用户现在能安全执行什么。

## 6. 文案体系

### 6.1 默认词汇

| 场景 | 使用 | 避免 |
|---|---|---|
| 工作区名称 | 固件更新 | 固件刷写、ROM 工具 |
| 新预设写入 | 安装到键盘 | 刷入、烧录预设 |
| 当前已安装预设修改 | 更新键盘中的此预设 | 应用、同步（含义不明时） |
| 浏览器副本 | 已保存到浏览器 | 已保存（省略位置） |
| 键盘当前预设 | 使用中 | activeId |
| 本地未写键盘 | 键盘中的此预设尚未更新 | 未同步（容易误解为云同步） |
| 自动路径无法继续 | 需要一次手动连接 | 致命错误、进入 ROM |
| 写入结束 | 写入完成，设备正在重启 | 升级已验证、设备已正常运行 |

技术术语只在高级选项、诊断日志或开发者文档出现。普通界面不展示 presetId、150B、Schema、NVS、HID Usage ID。

### 6.2 反馈分级

- **字段错误**：靠近字段，说明修正方法。
- **页面状态**：在固定状态区持续呈现，例如本地保存失败、设备断开。
- **任务结果**：在任务页或对话框中保留，不仅使用 toast。
- **轻量确认**：toast 只用于“已创建副本”等不需要后续操作的补充反馈。
- **危险确认**：统一使用页面对话框，列明对象、影响和取消入口，不再使用原生 `confirm()`。

## 7. 视觉基础：克制的新拟物控制台

### 7.1 方向

以 Neumorphism / Soft UI 为视觉语言：同一浅灰材质、左上光源、双阴影、柔和圆角。
它是实物键盘的控制台，不是层层嵌套的浮雕卡片。参考：
[主题规则](https://www.stylekit.top/zh/styles/neumorphism) 与
[showcase](https://www.stylekit.top/styles/neumorphism/showcase)。

- 平面用于纯内容和只读信息；凸起用于可点击控件；凹陷用于输入、当前激活和内容槽。
- 页面顶栏、导航容器、分段控件容器、左栏列表容器与右栏均以平面排版为主；只有当前条目自身凹陷，不使用外层与选中项叠加的双层凹陷。中央 SVG 键盘直接生长在页面材质上。
- 单选式效果卡片及其预览区默认保持平面，仅选中卡片整体凹陷并使用紫色标题，不叠加单选圆点、紫色选中描边或预览区凹槽；设备图等空间紧凑的槽位可保留选中描边。
- 持久选中与键盘焦点是两种独立状态；焦点仅通过 `:focus-visible` 的独立轮廓表达，不随鼠标选中常显，隐藏原生单选圆点时仍保留其键盘与无障碍语义。
- 底部保存区与固件主面板使用同一背景色，不使用玻璃态或深色设备画布。
- 不通过 hover 位移或放大阴影制造反馈；hover 缩小阴影，active 从凸起转凹陷。
- 减少边框、装饰线、渐变和嵌套卡片，用留白与材质建立层级。

### 7.2 颜色角色

| 角色 | 原型值 | 用途 |
|---|---|---|
| 页面与控件材质 | `#E0E5EC` | 统一背景和组件 |
| 抬升材质 | `#F0F0F3` | 轻微 hover 表面 |
| 凹陷/选中材质 | `#D1D9E6` | 当前项与选中键 |
| 暗阴影 | `#B8BCC2` | 右下阴影 |
| 亮阴影 | `#FFFFFF` | 左上高光，不作为页面背景 |
| 主文字 | `#333333` | 标题与正文 |
| 次文字 | `#596372` | 辅助说明；原型对背景实测约 4.80:1 |
| 主强调 | `#6D5DFC` | 主操作、当前状态、焦点 |
| 成功 | `#146B5D` | 已完成、已保留；正式页面对背景实测约 5.04:1 |
| 警告 | `#765800` | 可恢复风险 |
| 错误 | `#A63838` | 删除、失败与非法输入；正式页面对背景实测约 5.11:1 |

状态必须同时具有文字、图标或形状差异。预设主题色用于卡片标识和 SVG 灯点，不替代全局语义色。
参考风格的低对比规则不得覆盖 WCAG 与焦点可见性要求。

### 7.3 字体、间距与组件

- 使用舒适的中文系统字体栈；正文 15px，辅助说明通常 11–13px。
- 页面标题 28–33px，区块标题 20–23px。
- 使用 8px 间距基准；主要控件高度 40–44px，卡片条目约 58px。
- 圆角以 10–16px 为主，大容器可达 22–24px。
- 主按钮每个任务状态最多一个；危险操作使用明确文字与确认弹窗。
- 焦点环清晰，不依赖阴影深浅作为唯一焦点提示。

### 7.4 专用交互 SVG

`prototype/device.js` 使用独立视觉网格生成机身、12 个键帽、3 个编码器和 SideKey；保留物理识别特征，但不复用旧位图热点坐标，控件形状不得相互重叠。K2、中央旋钮、K8 与 K11 共享机身中央的 x=500 垂直中心线，顶行和方向键组围绕同一中心线对称；中央旋钮与 K2/K8 保持等距。K9 位于中央旋钮左下；左侧滚轮与大旋钮共享垂直中心线，大旋钮靠近左下区域。K4/K7 与 K5/K6 分别同宽同 X，两组横向间距一致。机身使用更充足的纵向空间，避免控件拥挤。
形状本身是热点，标签和选中状态直接附着在形状上；不再读取 `navio-chron-u1.png`。编辑 dirty 状态只在页面固定状态区呈现，不在键帽或旋钮上叠加易与灯点混淆的槽位圆点。
主题色灯点只出现在 12 个按键的中心偏上位置，编码器不添加灯点。键位映射模式隐藏灯点；灯光效果模式隐藏动作与名称，并隐藏状态灯灯芯、保留灯座，以减少预览干扰。真实设备状态灯不受灯效模式影响。K 编号和旋钮名称仅在悬停、焦点或选中时显示；旋钮名称统一位于控件内部上方，动作保留在中央，不再占用外部下方空间。未分配项默认留空，上下文中显示“未设置”，不使用会与加号键混淆的“＋”。
K4/K5 上方呈现 LED0–LED2 三个圆角横条状态灯，从左到右为电源、连接、当前预设，与 K1–K3 下边缘对齐，分别提供对应功能的 tooltip、焦点及可访问说明；它们不可编辑。品牌标记位于左上，品牌副标语固定为“Turn time. Tell your story.”。
实物渲染图以后只可用于介绍或帮助，不参与编辑定位。SVG 继续支持 Enter/Space、完整动作摘要和编码器三槽。

## 8. 响应式与可访问性

- 首要验收目标为桌面 Chrome / Edge 的 1280px 和 1440px 宽度。
- 较窄桌面下左栏可折叠为预设选择抽屉，设备图与检查器保持主要任务顺序。
- 单列布局按“当前预设 → 设备图 → 当前对象 → 写操作”排列，不把所有侧栏操作堆到顶部。
- 移动浏览器可以浏览已有内容，但不得暗示支持 WebHID 写入或固件更新。
- 所有热点、页签、菜单和对话框支持键盘操作；焦点顺序与视觉顺序一致。
- 200% 缩放时主操作、错误和确认内容不被裁切；文本对比度达到 WCAG AA。
- 滚动区域使用细滚动条、透明轨道和柔和圆角滑块，并以 stable gutter 避免布局变化。

## 9. 不变的安全与数据边界

- OTA 优先，受支持演示固件走既有自动迁移，其他情况进入一次 BOOT 救援。
- manifest、镜像摘要、芯片或能力检查失败时停止，不触碰设备或不写数据。
- 已知 Navio 保留预设；未知串口设备默认擦除并显式确认。
- 正常刷写完成后不自动重连验证；只有恢复中断 OTA 会话时保留必要重连。
- 本地修改不自动写键盘；同项覆盖和键盘删除保持显式确认。
- 键盘最多 6 套且至少保留 1 套；面向用户只提供逐套写入，不暴露非事务性的批量写入。
- 写入后立即重读并逐字节验证，成功后才清除对应 dirty 状态。
- 本地库损坏、存储失败和隔离条目继续按现有恢复规则处理。
